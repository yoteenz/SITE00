# 08 — Screenplay-to-screen pipeline

**Code:** `shared/site00-fiction-production/pipeline.ts` (stages and evaluator), `dispatch.ts` (spend gate, idempotency, retries), `approvals.ts` (approval domains). **State:** `THE_EXCHANGE/SEASON_1/PIPELINE_STATE_V1.json`, regenerated by `scripts/the-exchange/build-season1-production.ts`.

The evaluator is read-only. It derives each release's stage status from repository files and approval records. It never calls a provider, and nothing advances automatically into a paid stage. Approving a screenplay does not start generation.

## Stage statuses

`COMPLETE`, `AWAITING_APPROVAL`, `DRAFT_PENDING_UPSTREAM` (an artifact exists but an earlier stage is not complete), `READY`, `BLOCKED` (with listed blockers), `NOT_STARTED`, `FAILED_RETRYABLE`, `FAILED_TERMINAL`.

A stage is complete only when every stage before it is complete. A paid stage with all approvals and a spend authorization becomes `READY`, never `COMPLETE`, until a provider receipt exists.

## Dependency checks

- Stage 3 lists every hard conflict from the screenplay validator and the continuity engine for that release.
- Stage 5 compares the shot list's recorded screenplay SHA-256 with the current file. A mismatch blocks with "regenerate".
- Stage 6 lists every manifest blocker (face, set, wardrobe, prop, unregistered extra) and every character whose visual identity is not approved.
- Stage 7 lists every speaking character without an approved voice, and records that the voice provider is not verified.
- Paid stages add `UNAUTHORIZED_SPEND` until the founder records a spend authorization for that release and stage.

## Version lineage

Each stage evaluation carries its artifact path, the artifact's SHA-256, a version and the upstream hash it was built from (master row → screenplay hash → shot list hash). A changed screenplay invalidates everything downstream of it.

## Paid jobs: dispatch gate

`precheckProductionDispatch(job, context)` decides whether a job may be handed to a provider adapter. It returns a decision and spends 0 credits. It blocks, in this order:

1. `UPSTREAM_NOT_APPROVED` — the stage's approvals are not all recorded.
2. `SILENT_FALLBACK_ATTEMPT` — the job names a different provider from the one planned for the shot. No substitute provider and no substitute speech.
3. `PROVIDER_NOT_VERIFIED` — the provider has no verified generation capability. Today that is every generation provider.
4. `DUPLICATE_GENERATION` — an identical job already succeeded, is in flight, or failed terminally.
5. `UNAUTHORIZED_SPEND` — no founder authorization for the release and stage, or the job would exceed its credit or dollar cap (counting receipts and estimates already in the ledger).

The idempotency key is the SHA-256 of release, stage, shot, line, provider, model and inputs, with object keys sorted. Re-running the same job with the same inputs can never create a second paid generation.

## Recoverable failures

`openJob` → `recordFailure(retryable)` keeps the same key and allows a retry, up to 3 attempts. A non-retryable error or the third failure is terminal; the identical job is then blocked and needs changed inputs or a new founder decision. The stage does not advance on failure, and no other provider is tried.

## Cost tracking

- Estimates: each shot carries two alternative estimates from `PRODUCTION_TEST_RECORDS/PROVIDER_PRICE_QUOTES_V1.json` (OpenArt credits: 42 per keyframe + 175 per 5 s Kling block; fal: $0.28 per second billed in 5 or 10 s, plus $3 per minute for lip-sync). They are alternatives, not a sum.
- Actuals: `actualCost(ledger, release)` sums provider receipts only. With no jobs, actual cost is null.
- S1-01 to S1-05 together: about $178.22 on the fal route or 26,236 OpenArt credits. The OpenArt balance read on 2026-10-24 was 10,154 credits, so a full five-release run would need more credits or a cheaper plan.
